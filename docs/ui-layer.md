# Layer 3 — UI

*Host, theming, fonts, page structure and the interaction rules. For WHERE a
given piece of UI code belongs, see `docs/ui-file-layout.md` — this file covers
everything else about the UI layer.*

## Layer 3 — UI notes
- **File layout — read `docs/ui-file-layout.md` before adding a page, window, or shared widget.** `src/App.cpp` is a ~240-line **composition root** (`Run()`, `Update()`, `SwitchPage`, the ProductSession wrappers); every `Draw*` function is still an `App` member declared in `App.h` but **defined out of line** in a per-surface TU under `src/ui/pages/` or `src/ui/windows/` — the same multi-TU-one-unit shape as `command/Commands*.cpp`. No context structs, no friends. Rules: **page state stays an `App` member** (new file-scope *mutable* state in a page TU is a bug — UiSettings persistence and cross-page sharing both read App members; `constexpr` tables and anon-namespace helpers are fine); a helper lives in the file that uses it, and only moves to **`ui/Widgets.{h,cpp}`** when a second TU needs it (`StateColor`/`Glyph`/`Text`, `DeviceStatusLine`, `Splitter`, `FormatCurrent`, `MeasuredHz`, `KeiRangeIndexFor`, the `kFonts`/`kSteps`/`kKeiRanges`/`kUiSettingsPath` tables). **`Widgets.cpp` is the only UI TU that includes `windows.h`** (it backs `OpenFolderInExplorer`) and **`WndPrompts.cpp` the only one that includes `imgui_internal.h`** (`BringWindowToDisplayFront`) — keep both that way. When moving code between these files keep window/child/label strings and call order byte-identical (ImGui IDs derive from the runtime stack, not source location) and never mix a move with an improvement in one commit. CMake needs no edits — `GLOB_RECURSE … CONFIGURE_DEPENDS`.
- **`Theme`** (`src/ui/Theme.{h,cpp}`) — centralized ImGui styling as a table of selectable themes (FireDog Dark / Deep Blue / Graphite / Light). `Theme::Apply(index)` rebuilds the style from a fresh baseline (preserving `FontSizeBase`, which GlHost owns) and re-derives ImPlot's auto colors; the Display header's theme combo hot-switches it and the index persists in `UiSettings`. Every theme keeps `WindowRounding = 0` (multi-viewport OS windows) — put all global style/color tweaks here rather than scattering them across panels.
- **`GlHost`** (`src/ui/GlHost.h`) is our own thin host over GLFW + OpenGL3 + Dear ImGui. It owns the main OS window, the GL context, and the ImGui/ImPlot lifecycle. `Init` enables **both** `DockingEnable` and `ViewportsEnable` (multi-viewport = real extra OS windows). `EndFrame` renders the main window, then `UpdatePlatformWindows()/RenderPlatformWindowsDefault()` for detached viewport windows, restoring the GL context after. It exposes `MakeTextureRGBA()` (GL 3.0, via `opengl32`) so we don't depend on raylib for textures.
- **Window placement** — the main OS window's client rect and maximized state persist in `UiSettings` (`win_x/y/w/h`, `win_max`). `GlHost` owns them because it owns the window: `Init` takes a `WindowPlacement` and `Placement()` hands back what to save, so `App` never tracks a geometry it does not set. Three things make it behave: the settings are loaded **before** `host_.Init` and the window is created hidden, positioned, optionally maximized and only then shown (created-then-moved flashes at the default spot first); `TrackPlacement` samples the rect every `BeginFrame` but **ignores maximized and iconified frames**, so what is saved is always the *restored* rect an operator arranged; and a saved position that no longer overlaps any connected monitor's work area by 160x64 px is dropped (size kept) — unplug the second screen and the coordinates still parse perfectly while pointing at nothing. Floating ImGui windows (Aux / Jog / Organizer) keep their own places through ImGui's `imgui.ini`, which is a separate mechanism.
- **Fonts** — `GlHost::SetFont(ttfPath, sizePx)` / `SetFontSize(sizePx)` change the UI typeface/size (ImGui **1.92 dynamic fonts** — the backend owns the atlas texture via `ImGuiBackendFlags_RendererHasTextures`, so there is **no** `Create/DestroyFontsTexture`). Changes are **deferred to the next `BeginFrame`** (safe to call mid-draw): size is just `style.FontSizeBase`, and the atlas is only reloaded when the *typeface path* actually changes. A missing/bad path falls back to the built-in scalable font. Default is **Segoe UI 26 px**; the Display header offers a picker (`kFonts` table in `ui/Widgets.h`), persisted via `UiSettings`.
- **Main window** is paged (`Page` enum, Hardware menu): **Overview** (status / build identity (`core/BuildInfo`: git describe + commit, captured every build by `cmake/GitInfo.cmake`; built time = the exe's write time) + HALCON gates with the parsed licence files / log), **Camera** (connect/disconnect / exposure + pixel→mm calibration + preview / identity + stream info), **Keithley** (connect/disconnect / bias + NPLC/range/poll live tuning + chart / identity + live values), **CLD101x** (connect/disconnect / TEC + laser setpoints and on/off / identity + live values), **Motion** (PI + ACS: device list / large device name + tabbed detail — **Mapped Path** graph editor (the default tab; drag nodes, Edge mode links clicked nodes, right-click adds/deletes, From→To Go runs the path executor) + **Scanning** XCAN test bench / right panel = the device picture (up to 250×250; `<machine root>/config/device_images/<name>.png` wins over the shipped default `assets/devices/<name>.png`) over the selected device's **saved positions** table with its icon toolbar — the live axis table and
velocity combo sit under the device list on the left, so the saved-position
table gets the middle's full width), **IO** (device list / output toggles / live inputs), **Pneumatic** (slide list / Extend-Retract-Stop / sensor states). Every page uses the same three-panel layout (left list, middle detail, right live info) with draggable splitters whose pixel sizes persist in `UiSettings` and are shared across pages. Global F-key shortcuts activate pages: **F1** Run, **F2** Recipe Editor, **F3** Motion, **F4** Scripts (never with Alt — that is the OS close request), **F5** Alignment, **F7** Needle, **F8** Registration, **F9** Gripped object, **F10** Waffle Tray, **F11** Mosaic (F6 is free: it was the retired Placement page); a quick-access button strip under the menu bar offers the everyday ones and highlights the current page. They **activate**, never toggle, so the key for the page you are on does nothing. ALL page switches route through `App::SwitchPage` (`ToggleEditorPage` wraps it for the menu toggles): it owns the takeover/prevPage bookkeeping AND the dirty-recipe guard — leaving the Recipe Editor with unsaved edits blocks on the editor's Save/Discard/Cancel modal, which completes the deferred switch to `edLeaveTarget_`. Don't assign `currentPage_` directly — a caller with custom prevPage semantics (the Run deck's right-click shortcut) sets `prevPage_` itself and *then* calls `SwitchPage`. **A run outranks navigation.** While `orch_.Busy()` the dirty-recipe guard is skipped and the switch goes straight through: the guard is an ImGui *modal*, and a modal blocks input to every other window — including the always-on-top prompt / `manual_adjust` / align-pick windows an engine worker is blocked on. Raised mid-run it leaves the operator looking at a prompt they cannot click while the machine waits, and the run dies on the Stop that follows. The edits are not lost: they stay in memory, still dirty, and the guard fires the next time the machine is idle. Same rule inside the Recipe Editor itself — its editing surfaces gate on `orch_.Busy()` (not `recipe.Running()`, which blinks false between a program's queue items), Step and Next are disabled while `programs.Active()` because they would pause somebody else's run, and its Stop stops the *program* rather than one recipe out of the queue. The **IO Watch editor** and **Transforms editor** (View menu) are full-page takeovers of the main window — they replace the panel layout until their top-right Close button returns to the previous page (`prevPage_`); each edits a working copy (watch: Apply rebuilds the live watch, Save also writes `config/hardware.json`; transforms: edits hot-apply, Save writes `config/motion_transforms.json`). The **Alignment page** (View menu) is a takeover in the same family: procedure list (New/Duplicate/Delete/Save, dirty marker) | a header (name, device) over a **step selector** and ONE swappable pane | the taught frame as a record: E1/E2, origin, θ, span. The five steps are **E1**, **E2**, **Run alignment**, **Frame check** and **Teach nominal position**, and the selector reports as well as chooses — a dot per row: green/cyan/orange for a station (taught auto / taught manual / not finished), green on Run only while a LIVE frame exists, and green/red/orange on Frame check for what the guard band said about the last run. Stacked, as they were, all five were taller than the page and Run sat below the fold. A **station card** is the saved-position combo + Go + **Teach here** — which captures the current pose as a position private to the procedure: `algn_<procUid>_<n>`, `hidden`, dropped when the procedure is deleted — plus exposure, the lighting placeholder, Manual/Auto. **Run alignment** holds the button and the local→machine calculator (whose **Move here** drives to the computed XY behind the shared `jogArmed_` arming flag); **Frame check** holds the span/theta guard band, the run history and the Cp/Cpk of a repeatability sweep; **Teach nominal position** holds the nominal list. Run launches `alignment_procedure.lua` through the Lua engine — the page never captures a point itself; the crosshair pick surfaces in the global `DrawAlignPickWindow` (`WndPrompts.cpp`) exactly as it would for a recipe's `align_run` step, and that window is also where the guard band is drawn on the live image while E2 is marked. See `docs/alignment-procedure-design.md`. Separate windows: **Jog** (View menu; three tabs — **Jog**: the motion fleet, armed via checkbox, W/D·A/S·R/F keys, and Q/E to pick the step size — which sit OUTSIDE the arm gate, because choosing a distance moves nothing and reaching for the size before arming is the normal order; **Camera**: the camera fleet — device combo, the Camera page's exposure controls (shared via `DrawCameraExposureControls`), the live focus score + ROI combo, and the **Autofocus Z−** button, which runs the `auto_focus` command as a one-step ad-hoc recipe on the engine worker, gated on `jogArmed_` + `orch_.Busy()` — see `docs/vision-layer.md`; **Pos**: a 3×3 pad of one-click moves to taught positions — a device combo over its OWN copy of the Arm checkbox and the STOP button (a pad button starts a full travel, so what stops it must be under the same thumb), a nearest-taught “at …” readout, then nine buttons. Left-click drives there through the shared `StartWatchedMove`, so the travel reports in the status banner on whatever page the operator walks to; right-click opens the assign menu — a **popup, never a modal**, for the same reason the page-switch guard is skipped mid-run, and it stays reachable while disarmed because laying out the pad moves nothing. Assignments live in `UiSettings pos_pad`, keyed by device NAME so a fleet reorder cannot shuffle the pad, and hold position **uids**: a uid the loaded product does not contain is never cleared — the operator changed product, they did not unassign — the button just greys out until that product is back. Hidden `algn_…` positions are withheld from the assign menu, the rule the recipe picker follows; **IO**: a growable list of quick-output rows, each one button plus a dwell field in ms. A press toggles the pin when the dwell is 0, otherwise switches it ON and lets `Workflow::PulseIoOutput` switch it OFF after the dwell from the `Update()` tick — nothing blocks, and a press during the dwell switches it OFF now. Rows gate on `ioArmed_`, the IO page's own *Enable*, and NOT on `orch_.Busy()` — switching a light while a recipe waits at a prompt is what the tab is for. *+ Add row* appends; right-click assigns (device → pin submenu) or removes, a popup like the pad's. Rows persist in `UiSettings quick_io` as device NAME + pin NAME (index when unnamed), so a re-pinned config keeps them and one the fleet cannot resolve greys out rather than vanishing), the blocking **safety alert modal**, and the **Aux window** — camera image + Keithley ImPlot chart, whose view controls are a **vertical strip down the left edge, collapsible to one button** (`auxPanelOpen_`, persisted): Chart, Click-to-move, Arm jog, and the three image overlays — **Vision marks** (the last detection + E1/E2), **Grippers** (every registered device's tool tip, drawn only when it can be predicted — see `docs/device-registration-design.md`) and **Positions** with its `+hidden` sub-toggle. The strip sits on top of the picture the window exists to show, which is why it collapses, positioned outside the main viewport on first use so multi-viewport spawns it as its own OS window (drag to a second monitor).

The **Position History** window (View menu, Technician; also the Motion page's *History* button per device and each row's *Hist*; `ui/windows/WndPositionHistory.cpp`) shows the saved-positions change journal newest first — when (local time, UTC on hover), by whom, the source (hand / recipe / script / restore), the action, the axis values before → after with the delta — filtered by device and position (click a name to follow a deleted row), with **Restore** per update / rename / delete entry, disabled while `orch_.Busy()`. See `docs/state-and-config.md` (position change journal).

The **Scripts page** (F4, View menu; `ui/pages/PageScripts.cpp`, state in `ui/ScriptEditor.h`) is list | editor | run info over the Run/Pause/Continue/Step/Stop strip. The editor is ImGui's `InputTextMultiline` with a transparent text colour drawn over a syntax-coloured rendering of the same buffer, sized to the whole text so the child around it is what scrolls (design in `docs/lua-tier-design.md` §8 C4 — the two ImGui facts that make it work are recorded there). It offers Lua colour, a breakpoint gutter (click / shift+click range, hot-swapped into a live run), the executing-line arrow, auto-indent, Tab indent, completion (`fd.` members from the registry + the engine's binding table, keywords, library members, identifiers already in the file; Ctrl+Space forces it; Up/Down/Tab/Enter; a tooltip-layer popup so it never takes the keyboard), a compile-only syntax check 0.6 s behind the last keystroke, lint of `fd.<name>` and the unopened `os`/`io` libraries (clickable in the right panel), find (case-insensitive, Enter/Shift+Enter, marks on every match), Save (Ctrl+S; keeps the file's line endings), Revert, New. **Run is disabled while the buffer is dirty** — the engine runs the file — and the editor is read-only while `orch_.Busy()`. Leaving the page, clicking another script or Reload with unsaved edits raises the "Unsaved Script" modal (Save / Discard / Cancel), the Recipe Editor's shape, and `SwitchPage` skips it while a run is active for the same reason it skips the recipe one. A dirty buffer whose file dropped out of the list (product changed) stays open and says so; a clean one follows the list.
- **Dangerous actions are gated**: IO output toggles and pneumatic commands sit behind an armed checkbox (default ON as a kill switch); jog and Aux click-to-move (image click → `MoveGantryRelativeMM` via the `pixelToMm` calibration) default OFF and must be explicitly armed. The Aux window's image has two modes on its view strip, persisted as `aux_img_fit`: **Fill** (default, cover fit, the overflow cropped) and **Fit** (the whole frame letterboxed in the window); every overlay that lands on the picture (crosshair, cursor, vision marks, tips, the grip cross) projects into the IMAGE rect, the corner plates and the chart stay on the window, and a click on a letterbox bar moves nothing. Its signal chart grows with the window to a cap of 560 x 300 px so it never buries the picture; **Compact** (`aux_chart_compact`) halves that and is drawn BY HAND (`DrawAuxCompactChart`: polylines on the window draw list, one min/max per pixel column, each channel scaled to its own range, live values bottom-left) with no ImPlot and no child window, so it takes no input and a click on it reaches the image. Both charts (and the Keithley page's) share one **display low-pass** (`chart_smooth`, the **LP** combo on the chart's control row and on the Aux strip under Compact): Off / 50 ms / 0.2 s / 1 s, a time-aware EMA (`alpha = 1 - exp(-dt/tau)`, so the corner does not move with NPLC or the meter model) recomputed over the whole snapshot each frame in `UpdateKeithleyChartData` into `kF1_`/`kF2_`. The trace AND the printed value use it (`ChartV1/2`), tagged `LP <tau>` so a smoothed number is never read as raw. It is DISPLAY ONLY: the DataBus stream every recipe and scan reads, and the Keithley page's Live readout, stay raw - and an EMA lags a peak by about tau, which is why the presets stop at 1 s. Their **Y axis** uses **fixed ranges by magnitude** (`chart_y_bands_on` + `chart_y_bands`, in uA; default -1..10 uA, 10..1000 uA, 1000..10000 uA): auto-fit re-scaled on every sample, so a flat noisy current jumped. `App::ChartBandLimits` is the one mapping - the axis runs from the band holding the visible minimum to the band holding the maximum, widens at once, and narrows only when the data is 10 % of the narrower band clear of its edge (hysteresis, `ChartBandState`, so a signal on a boundary does not flip the axis); a value inside no band falls back to auto-fit. The compact chart applies it per channel. The ranges are edited in the **Preferences window** (`WndPreferences.cpp`, `kRolePrefs` = Operator, the *Preferences* button on the Overview's Hardware header): the Visual Studio *Options* shape - category tree (Environment > Display, Graphic view > Tool markers - the Aux view's per-device tip labels `aux_tip_labels`, default HL / HR, max 10 letters, with a preview of the edge triangle in the device colour -, Charts > Current (SMU) - also the channel(s) the chart shows at startup, `chart_ch_default` 0 Ch1 / 1 Ch2 / 2 both, default both, applied at every start and on Apply; the chart's own radio buttons are never saved -, Motion > Tool -> cam - the Jog window's registered-move row starts from these at every start and on Apply: Z offset `jog_reg_zoff_default`, 0 mm, and allow unverified `jog_reg_unverified_default`, on; the row's own edits are never saved; that page edits only at `kRoleJog`) | the selected page | OK / Cancel / Apply - editing a working copy (`prefsEdit_`) and writing back only what differs from `prefsBase_`. It is the only place theme and font are set (the Overview's old Display block is gone). Non-modal, like every surface a run may be blocked behind. The Aux window's cursor crosshair + dX/dY readout only draw while click-to-move is armed (they describe the move a click would command); its gantry-main **Z arrows** (up = Z−, down = Z+, step from a short `kSteps` subset) go through `Workflow::JogGantryZ` and share the Jog window's `jogArmed_` flag, exposed there as the "Arm jog" checkbox. While jog is armed the picture carries the four jog keys at its edge midpoints (W top, S bottom, A left, D right, and the Z pair R/F with drawn up/down arrows stacked in the bottom-right corner, in violet so the focus axis never reads as a lateral one; `DrawAuxJogKeys`): coloured while the keys are LIVE (the Jog tab stamps `jogKeysLiveFrame_` each frame it is armed, focused and connected - a frame stamp, so a closed window or another tab reads as not live), dim with a "click the Jog window" hint otherwise, and each box flashes the pad's hot amber on a stroke (the shared `jogKeyFlashAt_`, fading over 0.35 s via `KeyGlow`, held lit while the key is down). Display only. The Aux window's bottom-left **position plate** names where each stage stands — gantry-main / hex-left / hex-right, each device's live pose (`Workflow::DevicePose`, layer 2 does the fleet lookup) matched to the nearest saved position of that device via the shared `NearestSavedPos` (`core/SavedPositions.h`). Green when within 0.050 mm of it, amber with the distance otherwise; a device that is absent or disconnected drops off the list. Positions belong to the loaded product, so the same axis reading is a name under one product and unnamed under another. Hidden positions are candidates by default (the **+hidden** checkbox, persisted as `pos_labels_hidden`), because this answers where the stage *is* and naming a neighbour instead would be a lie — turning it off trades that for keeping the `algn_...` system names out of the plate. It is drawn straight onto the draw list, never into a child window, so it cannot swallow a click-to-move. Toggled by the "Positions" checkbox, persisted in `UiSettings`. The Aux plate also carries an **Autofocus** button + direction combo — the second launcher of the Camera tab's sweep (same App state, same `StartQuickAutoFocus`, same `jogArmed_` + `orch_.Busy()` gates); range and step stay in the Camera tab.
- **Image + overlay**: upload frame via `GlHost` textures, show with `ImGui::Image`, then draw vision overlays with `ImGui::GetWindowDrawList()` in the same screen coords. Keep textures in windows on the **main** GL context; ImPlot charts are pure vector geometry so they render in any viewport.
- **Log viewer** (`core/Log.{h,cpp}`): `Logger` ringbuffer, snapshotted by the UI with level filter + autoscroll.

**Why not raylib:** raylib is single-window by design (`InitWindow` once, one global GL context), so a real second OS window is impossible and ImGui multi-viewport can't be enabled through rlImGui. Owning a GLFW host removes that ceiling. Do not reintroduce raylib/rlImGui.
