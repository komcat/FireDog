# Config, persisted state & the DataBus

*Where every piece of state lives, which file it persists to, and the fallback
rules. `ProductSession` is the single owner of the product document — see also
`docs/ui-file-layout.md` for how the UI reads it.*

## Config

- **`config/hardware.json`** — consolidated device config, sections: `cameras`, `instruments` (Keithley / CLD101x / UDP3305S PSU, split by `type`), `motion_devices` (PI/ACS), `io_devices` (eziio/wago, with per-pin `pins` name maps), `pneumatic_slides`, `io_watch`, `safety_watch`. Loaded by `HardwareConfig::Load` (tolerant/nlohmann; struct-per-section in `HardwareConfig.h`). Copied next to the exe at build time; the app reads it relative to cwd. `HardwareConfig::SaveIoWatch` writes ONLY the `io_watch` section back (read-modify-write) — but a rebuild recopies the repo's `config/` over the exe-side copy, so mirror durable edits into the repo file too.
- **`config/motion_transforms.json`** — per-device global→local `AxisTransform` (identity default): a 3×3 `Matrix` for translation and an optional 3×3 `Rotation` block (global U/V/W = θx/θy/θz → local rotational axes). Both are signed-permutation columns (column j = where global axis j goes). Used by Workflow's jog kinematics (`JogGlobal`/`JogGlobalRot`); editable live in the **Transforms Editor** page (View menu) — every edit hot-applies via `SetTransforms`, Save writes the file (same exe-side/rebuild caveat as `SaveIoWatch`).
- **Motion maps** — `core/MotionMap.{h,cpp}`: node-edge graphs over saved positions ("Mapped Path" tab on the Motion page). A node references a SavedPos **uid** (one node per position per map) plus editor canvas x/y; edges are **bidirectional** and encode which direct moves are safe; devices can have several maps. Persisted machine-global as `config/maps.local.json` (`maps.json` fallback), autosaved on every structural edit. `FindMapPath` is Dijkstra with a caller-supplied cost (the UI uses XYZ distance between the two positions). Map *geometry* lives here, not in the UI: `BuildMapRoute` plans a route (shared by the Go button and `move_path`) and `NearestMapNodeUid` resolves the Go combo's "(nearest node)" start — both must agree on how a node maps to a pose, so keep them together. Execution is Workflow's **path executor**: `StartPathMove(devIdx, waypoints)` issues the first leg and `TickPath` (from `Update`) watches live positions — arrival = every targeted axis within 0.01 mm — then issues the next leg (120 s/leg timeout). One path at a time; a safety STOP (via the atomic `pathCancelReq_`), a manual device Stop, or `CancelPathMove` abandons it.
- **Saved positions** — `core/SavedPositions.{h,cpp}`: one JSON for all devices keyed by device name, `config/positions.local.json` with `positions.json` fallback (the project's `*.local.json` convention — local files gitignored). Positions carry a stable `uid` (recipes/programs will reference it; renaming changes only the label) and can be `hidden` (system positions).
- **Products** — `core/Product.{h,cpp}`: a product is a folder under `products/` (next to the exe) with a `manifest.json` naming uid-stamped core files (`{uid}.positions.json` / recipes / programs) plus `data/` and `images/` subfolders. When a product is loaded (File menu; last product auto-reloads at startup via `UiSettings`), saved positions persist into the product's positions file instead of `config/positions.local.json`.
- **`ProductSession`** (`session/ProductSession.{h,cpp}`) — the application document and the ONE owner of everything above: product manifest + positions + maps + recipes + programs + scripts, plus the product-file → `config/*.local.json` fallback rules for each, the dirty baselines (`RecipesDirty`/`ProgramsDirty`, snapshot-compare), `LoadInitial`/`LoadProduct`/`NewProduct`/`SaveProduct`, `MergeTaughtPositions` (the `save_position` teach drain — called from `App::Update`, the worker→UI hand-off point), `SeedHomePosition` (a device with no positions gets a zeroed "Home" — also driven from `Update`, because it needs the axis list the async connect produces, and **a Draw function must never mutate the document**), and **`MakeRecipeEnv()`/`MakeLuaEnv()`**, the only place a run's `Env` is built. **UI-thread only, no locks**: engines get a *copy* at Start (copy-at-Start IS the concurrency contract), which is why the collection accessors hand out mutable refs. `App` owns it as `session_` and keeps only UI selection state (`recipeSel_`, `progSel_`, `scriptSel_`, …), re-pointed after a reload by `App::ResetDocumentSelections()` — the session never calls back into the UI.
- **UI prefs** — `ui/UiSettings.{h,cpp}`: font, panel splitter sizes, view toggles, last product — a gitignored `*.local.json` next to the exe. All loaders are tolerant: missing/malformed files yield defaults, never throw.

## Pub-sub — `DataBus` (`src/core/DataBus.{h,cpp}`)
Process-wide, thread-safe publish/subscribe for measurement streams. `DataBus::Instance().Stream("<topic>")` returns a stable `DataStream` reference; publishers `Publish(t, value)`, consumers push-`Subscribe(callback)` or pull `Snapshot(t, v)` (what the immediate-mode Aux chart does each frame). Topic names live in `core/Topics.h` — never hard-code the strings: `keithley/ch1|ch2`, `motion/<device>/<axis>`, `io/<device>/in|out` (pin bitmask as double, published only on change). Add new device streams by publishing to a new topic — no wiring changes needed on the consumer side.
