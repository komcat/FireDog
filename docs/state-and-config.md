# Config, persisted state & the DataBus

*Where every piece of state lives, which file it persists to, and the fallback
rules. `ProductSession` is the single owner of the product document — see also
`docs/ui-file-layout.md` for how the UI reads it.*

## Config

- **`config/hardware.json`** — consolidated device config, sections: `cameras`, `instruments` (Keithley / CLD101x / UDP3305S PSU, split by `type`), `motion_devices` (PI/ACS), `io_devices` (eziio/wago, with per-pin `pins` name maps), `pneumatic_slides`, `io_watch`, `safety_watch`. Loaded by `HardwareConfig::Load` (tolerant/nlohmann; struct-per-section in `HardwareConfig.h`). Copied next to the exe at build time; the app reads it relative to cwd. `HardwareConfig::SaveIoWatch` writes ONLY the `io_watch` section back (read-modify-write) — but a rebuild recopies the repo's `config/` over the exe-side copy, so mirror durable edits into the repo file too.
- **`config/motion_transforms.json`** — per-device global→local `AxisTransform` (identity default): a 3×3 `Matrix` for translation and an optional 3×3 `Rotation` block (global U/V/W = θx/θy/θz → local rotational axes). Both are signed-permutation columns (column j = where global axis j goes). Used by Workflow's jog kinematics (`JogGlobal`/`JogGlobalRot`); editable live in the **Transforms Editor** page (View menu) — every edit hot-applies via `SetTransforms`, Save writes the file (same exe-side/rebuild caveat as `SaveIoWatch`).
- **Motion maps** — `core/MotionMap.{h,cpp}`: node-edge graphs over saved positions ("Mapped Path" tab on the Motion page). A node references a SavedPos **uid** (one node per position per map) plus editor canvas x/y; edges are **bidirectional** and encode which direct moves are safe; devices can have several maps. Persisted machine-global as `config/maps.local.json` (`maps.json` fallback), autosaved on every structural edit. `FindMapPath` is Dijkstra with a caller-supplied cost (the UI uses XYZ distance between the two positions). Map *geometry* lives here, not in the UI: `BuildMapRoute` plans a route (shared by the Go button and `move_path`) and `NearestMapNodeUid` resolves the Go combo's "(nearest node)" start — both must agree on how a node maps to a pose, so keep them together. Execution is Workflow's **path executor**: `StartPathMove(devIdx, waypoints)` issues the first leg and `TickPath` (from `Update`) watches live positions — arrival = every targeted axis within 0.01 mm — then issues the next leg (120 s/leg timeout). One path at a time; a safety STOP (via the atomic `pathCancelReq_`), a manual device Stop, or `CancelPathMove` abandons it.
- **Saved positions** — `core/SavedPositions.{h,cpp}`: one JSON for all devices keyed by device name, `config/positions.local.json` with `positions.json` fallback (the project's `*.local.json` convention — local files gitignored). Positions carry a stable `uid` (recipes/programs will reference it; renaming changes only the label) and can be `hidden` (system positions — kept out of the Motion page table unless "Reveal hidden rows" is ticked, and never *offered* by the recipe editor's position picker, though an existing reference still resolves). The Alignment page uses that flag for its **private station positions** (`algn_<procUid>_<station>`, taught with the station card's Teach button and deleted with the procedure) — see `docs/alignment-procedure-design.md` §6.
- **Position change journal** — `core/PositionHistory.{h,cpp}`: an append-only JSONL beside the positions file in use (`{uid}.positions.history.jsonl` in the product folder, `config/positions.local.history.jsonl` before a product is loaded — gitignored), one line per visible add / update / rename / delete with the UTC stamp, the signed-in operator (`ProductSession::SetPositionAuthor`, written by `App::LogIn` alone, like the DUT operator), the source (`hand` for a Motion page button, `recipe <name>` / `script <name>` for the teach drain, `restore of <action> @ <stamp>` for a Restore), and the axis values before and after. Entries are produced by **diffing** the map about to be written against `positionsBaseline_` (what was last loaded or written) inside `ProductSession::SavePositions` — the one choke point every writer already goes through — so no call site records a change and none can forget to; a rewrite of identical numbers is not a change (1e-6 mm), and a row that moved and was renamed yields two entries so each restores on its own. Hidden positions are never journalled. Kept for ever (an entry is ~200 bytes); `NewProduct` copies the journal along with the positions it carries over. The **Position History** window (View menu; the Motion page's *History* button for a device and the selected row's *Hist*) lists it newest first, filtered by device and position, and **Restore** writes an entry's old state back through `RestorePosition` (values for update, the name for rename, the row re-created under its uid for delete) — which saves like any edit and so appends its own entry: the journal never loses the state it restored from.
- **Products** — `core/Product.{h,cpp}`: a product is a folder under `products/` (next to the exe) with a `manifest.json` naming uid-stamped core files (`{uid}.positions.json` / recipes / programs / alignments / vision / grips / trays) plus `data/`, `images/` and `vision/` subfolders. `EnsureManifestRole` backfills a role an older product predates, at **load** time. When a product is loaded (File menu; last product auto-reloads at startup via `UiSettings`), saved positions persist into the product's positions file instead of `config/positions.local.json`.
- **Alignment procedures** — `core/AlignFrame.{h,cpp}`: a named, uid-stamped procedure that teaches a rigid 2-D **local frame O1** (origin + rotation about Z) from two operator-marked features E1/E2 at two gantry stations. Product data: manifest role `alignments`, file `{uid}.alignments.json`, with the `config/alignments.local.json` → `alignments.json` fallback. Persistence follows the *recipes* model (explicit Save + dirty baseline) because a procedure is a document — except the **taught frame**, which `ApplyAlignResult` persists the moment `align_solve` produces it. Older products get the manifest entry backfilled by `EnsureManifestRole` at load. Design: `docs/alignment-procedure-design.md`.
- **Vision detection models** — `vision/VisionModel.{h,cpp}`: a uid-stamped detector (search ROI, method `circle`|`ncc`, that method's parameters, an optional taught template, a reliability record), **private to one alignment station** and auto-named `vdet_<procUid>_<station>` — the name is the ownership record, exactly like the private station positions, so deleting the procedure drops it and duplicating copies it. Product data: manifest role `vision`, file `{uid}.vision.json`, with the `config/vision.local.json` → `vision.json` fallback. Same persistence model as recipes and alignment procedures (explicit Save + dirty baseline) — a half-tuned detector must not reach the next run — except a **teach**, which saves immediately because the `.pgm` is already on disk. Taught patches are 8-bit PGM under `ProductSession::VisionDir()` (`products/<name>/vision/`, else `config/vision/`, gitignored), named `<modelUid>.pgm` and stored **relatively** so a product folder stays relocatable. The model OWNS that file: `DeleteVisionModel` removes it, Duplicate copies it under the new uid, `NewProduct` copies every patch into the new product. Design: `docs/vision-detection-design.md`.
- **Gripped-object profiles** — `core/GripProfile.{h,cpp}`: a named, uid-stamped profile saying how to measure where the object in one gripper's jaws sits — the private inspect pose (`grip_<uid>_i`, hidden), the find mode with its private detector (`vdet_grip_<uid>`), the object's width with a tolerance, and the reference offset a good grip has. Product data: manifest role `grips`, file `{uid}.grips.json`, with the `config/grips.local.json` → `grips.json` fallback; same persistence model as alignments (explicit Save + dirty baseline), except `ApplyGripResult`, which records what a run MEASURED and never what it decided. Product state rather than machine state — the opposite of `DeviceReg` and for the opposite reason: a lens is part of a product. Design: `docs/gripped-object-design.md`.
- **Waffle trays** — `core/WaffleTray.{h,cpp}`: a named, uid-stamped grid of positions on one motion device, taught from three corners (origin (1,1), row end (1,C), far corner (R,C), each every axis the device reports, in its own axis space) plus `rows × cols` and masks (`disabledRows/Cols/Cells`). `TrayCellPose` derives any cell; the corners are coordinates, never position uids. Product data: manifest role `trays`, file `{uid}.trays.json`, with the `config/trays.local.json` → `trays.json` fallback; same persistence model as grips (explicit Save + dirty baseline), except a corner teach and a device change, which save on the spot. `NewProduct` carries trays over intact, used cells included. The **used cells** (`usedCells` — the cavity is empty) are part of the record and save on the spot whenever they change: a run's `tray_next` marks the live cursor on `Workflow` and queues the change (`TakeTrayUsed`, drained in `App::Update` into `SetTrayCellsUsed`), the page marks through `App::SetTrayCellsUsed`, and product load re-seeds the cursor from the file. Design: `docs/waffle-tray-design.md`.
- **`ProductSession`** (`session/ProductSession.{h,cpp}`) — the application document and the ONE owner of everything above: product manifest + positions + maps + recipes + programs + scripts + alignment procedures + vision detection models, plus the product-file → `config/*.local.json` fallback rules for each, the dirty baselines (`RecipesDirty`/`ProgramsDirty`/`AlignsDirty`/`VisionDirty`, snapshot-compare), `LoadInitial`/`LoadProduct`/`NewProduct`/`SaveProduct`, `MergeTaughtPositions` (the `save_position` teach drain — called from `App::Update`, the worker→UI hand-off point), `SeedHomePosition` (a device with no positions gets a zeroed "Home" — also driven from `Update`, because it needs the axis list the async connect produces, and **a Draw function must never mutate the document**), and **`MakeRecipeEnv()`/`MakeLuaEnv()`**, the only place a run's `Env` is built. **UI-thread only, no locks**: engines get a *copy* at Start (copy-at-Start IS the concurrency contract), which is why the collection accessors hand out mutable refs. `App` owns it as `session_` and keeps only UI selection state (`recipeSel_`, `progSel_`, `scriptSel_`, …), re-pointed after a reload by `App::ResetDocumentSelections()` — the session never calls back into the UI.
- **UI prefs** — `ui/UiSettings.{h,cpp}`: font, panel splitter sizes, view toggles, the main window's place on screen, last product, the Jog window's Pos pad (`pos_pad`) and quick-output rows (`quick_io`) — a gitignored `*.local.json` next to the exe. All loaders are tolerant: missing/malformed files yield defaults, never throw.

## Pub-sub — `DataBus` (`src/core/DataBus.{h,cpp}`)
Process-wide, thread-safe publish/subscribe for measurement streams. `DataBus::Instance().Stream("<topic>")` returns a stable `DataStream` reference; publishers `Publish(t, value)`, consumers push-`Subscribe(callback)` or pull `Snapshot(t, v)` (what the immediate-mode Aux chart does each frame). Topic names live in `core/Topics.h` — never hard-code the strings: `keithley/ch1|ch2`, `motion/<device>/<axis>`, `io/<device>/in|out` (pin bitmask as double, published only on change), `camera/focus`, and `vision/x_px|y_px|score|angle_deg|ok` (published by `Workflow::Detect` on every run — misses included, as `vision/ok` = 0, so a reliability sweep counts them). Add new device streams by publishing to a new topic — no wiring changes needed on the consumer side.
